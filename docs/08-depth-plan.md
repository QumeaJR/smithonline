# Depth plan: from a Smith chart tool to a matching workbench

Status: plan, 2026-10-25. Follows the assessment of what a senior RF design engineer would do with this app that the owner did not ask for: deeper, not bigger. Every phase ends with a QA round (qa-validator, adversary, ui-expert) and its fixes, like the interaction redesign.

## Principles

- The measured load is the central object, not a single R + jX: a design is judged over the band, against data.
- Results are proven by something other than the authors: physics invariants, an independent simulator, published answers, and in the end a built board on a VNA.
- Real parts and the real board belong in the network: part numbers with measured behaviour, pads, vias and the traces between parts.
- Depth before breadth: each phase deepens what exists (the load, the realization, the optimizer, the broadband search) rather than adding a new view.

## Phases

### D1. Verification foundation

Proves the core right before anything is built on it.

- Physics invariants as property tests over random networks of every element kind: reciprocity (S12 = S21), lossless networks keep S†S = I, passive networks keep |S11| ≤ 1 and the eigenvalues of I - S†S non-negative, ABCD determinant 1 for reciprocal two-ports, cascading in either grouping gives the same result, conversions S, Z, Y, H, ABCD round trip.
- Published answers as golden tests, each with its source in the test: worked examples from Pozar (Microwave Engineering), HP AN 95-1 (in `original/`), Bowick (RF Circuit Design), the Bode-Fano example in Pozar, and the numbers printed in `original/Examples V4.1.pdf` for the 22 example projects.
- An independent simulator as an oracle in CI: a GitHub Actions job installs Python with scikit-rf and ngspice, a node script exports a set of reference networks (every element kind, lossy and lossless, lines and stubs, realized and packaged) with the app's computed S-parameters, and a Python script recomputes them with scikit-rf and with ngspice from the app's own SPICE export, failing above 1e-9 relative error (1e-6 for ngspice). Locally the invariant and golden tests run in Vitest; the oracle runs in CI only, because no Python is installed here.
- Done means: invariants hold on 10 000 random networks; every golden case matches its source to the printed precision; the oracle job is green in CI.

Status, 2026-10-25: implemented, the oracle green in CI since run 40178095887; the QA round's fixes are in (below).

- Invariants: `packages/core/test/invariants.test.ts`, 10 000 seeded random networks (6 000 ladders, 2 000 lossless; 2 000 conversion round trips; 2 000 closed-form matches) plus eight broadband searches against the exact Bode-Fano floor of single-reactance loads. They found one defect: `ladderSParameters` took S12 as 2 det(ABCD) / Delta, and the determinant of a ladder with a very lossy line is the difference of two products that grow as exp(2 alpha l), so beyond about 160 dB of line loss S12 had no correct digit (in a cascade it came out above 1, breaking passivity). S12 is now S21, exact for every ladder; a regression test keeps it. The Bode-Fano comparison is on the dense grid every broadband result is now scored on (see the QA round), not on the 21 band points.
- Golden cases: `packages/core/test/golden.test.ts`, 26 cases with their sources (Pozar 4th ed. chapter 5 and tables 8.3, 8.4; Matthaei, Young and Jones; HP AN 95-1; Smith V4.1 Examples 5, 6, 12 to 14, 16 to 18; Bowick's procedures). Values a book computed from a rounded intermediate are checked against that intermediate and say so. Left out because they cannot be reproduced to the printed precision: the ADS simulation results printed for Example 13 (ADS uses its own device and part models; the app's cascade gives S21 12.009 dB against 12.005, S22 impedance 49.65 + j1.29 against 49.22 + j1.31 ohm, NF 3.8526 against 3.852 dB), Pozar's Chebyshev Gamma_0, Gamma_1, Z1 and Z3 (rounded sec theta_m; Z1, Z3 not confirmed), and every number of the Examples PDF that exists only in its screenshots (the text layer has no images and drops the plus and minus glyphs).
- Oracle: `tools/oracle/export.mjs` (27 reference networks, 23 with a netlist, four of them through the app's own export code), `tools/oracle/check.py` (scikit-rf 1e-9, the `.s2p` text round trip 1e-8, ngspice 1e-6, `--self-test`), CI job `oracle` with the report as an artifact, Python packages pinned to the green run (scikit-rf 2.2.0, numpy 2.5.4). The JSON semantics were checked locally against a JavaScript port of `check.py`'s element models (agreement 1e-15, the round trip 8e-10) and every netlist against the repository's nodal solver (1e-9, the open stubs' 1 Tohm far end); the Python could not be run locally (no Python installed). What the oracle checks independently (scikit-rf cascading, renormalization and S conversion; ngspice's nodal solution) and what it shares with the app (the element formulas: Q, ESR, Cp, ESL, pads, the lossy line's attenuation scaling, the transformer closed form) is listed in `tools/oracle/README.md`.
- QA round (qa-validator, adversary): broadband results were scored at the band points only (as few as 5), so with many parts the optimizer fitted the points and the response swung between them (reported 3.67, true worst 992). Every candidate is now scored on a dense grid inside the band (at least max(201, 25 per part) points, the band points included, the same load model as the search); the search itself uses at least 4 points per part plus 1, and the panel's band at least as many. A result below Fano's exact floor of a single-reactance load is never listed. The Bode-Fano floor is not shown for fewer than 9 band points (the panel says why: a five-point slope window could put it above the physical bound), and where the load is a single reactance with a resistance (series RL or RC, parallel RC or RL) it is Fano's exact bound with the band edges, labelled exact; elsewhere the Yaghjian-Best estimate, labelled as an estimate (it can be off either way for low-Q loads). D2's floor from the fitted load model supersedes both. K, mu and mu prime within 1e-9 of 1 are 1, so a lossless network reads MAG = MSG = 0 dB without the unstable style (the S-Plot network entry keeps 15 digits, the download 9). S12 from an ABCD matrix is S21 when the determinant is 1 within its rounding (`abcdMatrixToS`, `abcdToS`), and `ladderSParameters` refuses an element kind not marked reciprocal. Golden: Example 14's part values to 3 digits, Example 16 renamed (the PDF names no series), Pozar 5.6's bandwidth annotated (the ln approximation for A; exact A gives 0.713).

### D2. Measured load first

- Vector fitting (Gustavsen and Semlyen, with relaxation) turns a measured S11 or impedance set into a rational model with passivity enforcement; the app uses it for honest interpolation between frequency points (replacing linear interpolation in `interpolatedLoad`) and flags extrapolation outside the measured band.
- A measured load (from Touchstone, CITI, VNA CSV) becomes a first-class load: the design frequency picks the nominal point, the whole band drives Auto match Broadband, Optimize band, usable bandwidth, Monte Carlo over the band and the Response view, with the fitted model's residual shown.
- The Bode-Fano floor computed from the fitted model, not only from a finite-difference Q.
- Done means: fitting recovers a known rational load to 1e-9, a noisy measurement to its noise floor, passivity holds after enforcement, and every band tool uses the fitted load.

Status, 2026-10-25: implemented; QA round done (below).

- Vector fitting: `packages/core/src/vectfit.ts`. Relaxed pole relocation in normalized frequency (starting pairs at -0.01 b + j b, log spaced for a band of a decade or more, linear otherwise), residues by Householder least squares with unit-norm columns, eigenvalues by balancing, elimination to Hessenberg form and shifted QR; unstable poles flipped; the pole relocation uses at most 300 evenly picked points, the residues and residuals all of them. The order runs from 2 upward and stops at an RMS target or after three orders without a 10 % improvement (cap 2N/3 and 30); the lowest order within 10 % of the best RMS is kept. Passivity of a reflection model: |Γ| on a grid of max(2001, 20 per point) points from 0.9 times the lowest to 1.1 times the highest frequency, each local maximum refined by golden section; the violating maxima are pushed to 1 - 1e-10 by the smallest residue and d change over the data points (linearized, up to 50 steps), and whatever remains is removed by scaling the model. Checked on the grid only.
- Accuracy (`packages/core/test/vectfit.test.ts`): a known rational impedance (two pairs and a real pole, d and e) is recovered to 1e-15 relative in poles and residues (the test asks 1e-9), at the given order and automatically; series RLC, parallel RLC and a two-resonance antenna (two series RLC branches in parallel behind 2 nH), 401 points, fit clean data to 1e-15 and noisy data to the noise floor: at noise 1e-4, 1e-3 and 1e-2 in Γ per part the RMS residual is within 10 % of the noise RMS (3.99e-4 to 4.00e-4 against 4.08e-4 at 1e-3) and the model lies a tenth of the noise from the truth (worst 4.5e-5, 4.5e-5 and 7.0e-5 at 1e-3; orders 2, 2 and 4). A lossless load with noise on the rim (|Γ| up to 1.00005) ends at |Γ| ≤ 1 on a 20 001 point grid by perturbation; data with |Γ| = 1.2 is scaled to passive. Times: under 35 ms for 1601 points.
- The measured load: `packages/core/src/measured.ts`, `interpolatedLoad` (cached per point list and Z0). Fitted from 6 points at the design's Z0; used when the largest residual is at most 0.01 in Γ; followed 5 % past the data and held beyond; linear interpolation (held at the end points) otherwise. In the app (`packages/app/src/lib/measuredLoad.ts`) the measured load is the imported points of a datapoint sweep; Back to frequency sweep returns to the fixed load. Broadband, Optimize band, Tolerance over the band, the usable bandwidth, the Response view and the broadband tour use it; the workers rebuild the model from the points.
- The floor (`fittedFeasibility` in `optimize.ts`): the model sampled on 201 points across the band, tested against the four single-reactance forms (1e-3) and then Fano's exact bound with the element values read from the model; otherwise the Bode-Fano bound with the Yaghjian-Best Q from the model's analytic derivative at the geometric band centre (exact for series RL and a resonant series RLC centred in the band, an estimate otherwise). For series RL, series RC, parallel RC and parallel RL, clean and with noise 1e-4, the floor equals Fano's exact bound within 1 percent (observed within 1e-15 clean and 5e-6 with noise 1e-4). A broadband candidate is kept within 1e-3 of an exact floor read from a fitted model.
- Oracle: `tools/oracle/export.mjs` writes three fitted loads (`fits`), `check.py` checks them (see `tools/oracle/README.md`). The Python was not run locally (no Python installed); its checks were run through a JavaScript port against the exported cases (evaluation 1e-15, model against the truth 1.4e-15 clean and 1.5e-4 with noise 1e-3, residuals, stability, passivity, the series RL floor within 2e-16 of Fano's closed form).
- QA round (qa-validator, adversary, ui-expert): the fit was accepted on its residual at the rows only, so with few or noisy rows the order search could put a sharp resonance between two rows (8 rows of a series RLC rounded to 3 decimals: order 4, a pole of Q 2400 between two rows, 0.365 off the load in Γ there, a floor of 3.33 above the best listed match of 1.93). Now: a complex pole pair whose damping is below half the row spacing where it resonates (inside the data or 10 % past it) is dropped and the residues refitted; the chosen model is checked at four points inside every interval against the rows' linear interpolation and, below 30 rows, by leaving three rows out and refitting, allowing 0.01 plus the data's own change over the interval; a model that fails falls back to the next lower order, and when none passes the load is linear interpolation (reason `between-points`); the order cap is N/3 below 20 rows. The 8-row case: order 2, 0.0022 from the load anywhere (was 0.365), floor 1.01 under the best match 1.73, the best two-part match on the model 1.331 against 1.331 on the load (was 2.19); noisy 11-row sets: none of 40 off by more than 0.05 (was 3). The order search steps by pole pairs, goes on while no order meets the 0.01 tolerance, and once one does stops at the target or after three pole pairs without a 10 % gain (one real pole fewer is taken when it does as well): four parallel series-RLC branches order 8 to 3e-15 (was order 6, 0.20), Γ = 0.5 exp(-jw 2 ns) order 18 to 1.4e-6 (was order 2, 0.60), 1 Ω + 0.3 nH behind 0.55 ns order 12 to 2.8e-6 and fitted (was linear at 1.2). The pole relocation iterations are tracked on the relocation subset and the residues found once from all rows, so 10 001 rows fit in 65 to 600 ms (was 4.4 s); the app fits in a Web Worker (linear interpolation, "fitting the model", until it is ready). Passivity: the check points include the frequencies where |Γ| crosses 1, from the eigenvalues of the model's Hamiltonian matrix, and the points between them, so no violation inside the check range lies between grid points unseen; the passive model with the smallest residual is kept, the perturbation stops once it misses the rows by more than the fallback does, and the fallback scales the original fit (the noisy lossless case: 7.4e-4 and fitted, was 0.034 and linear after 50 perturbations scaled the damaged model). |d| is reported, not enforced (the model is used only near the band). The floor estimate from a fitted model is null when the band's geometric centre lies outside the data, and its `fractionalBandwidth` is referred to the geometric centre the floor uses. App: Broadband follows the load of every band tool (no own checkbox), its band follows a new import until edited and a band wholly outside the data is refused; DP1 follows the design frequency over a measured load (the row nearest f); the usable bandwidth is clamped to the data ("reaches the end of the data at ..."); the log frequency axis spans the data; the Response view scrolls so the readout never covers a plot, and lists Load alone; Tolerance over the band names the band and gives the spread of the band worst case; Broadband drops parts pinned where they do nothing and lists each shape once; Optimize band prints its worst VSWR on Broadband's dense grid; the tours read the same load as the readout. Oracle: a fourth fit case, a lossless series LC with noise, starts non-passive and checks the enforcement.
- No existing test relied on linear interpolation between six or more points; every one passes unchanged. The broadband tour's synthetic antenna (61 points of series RL) is now fitted, which gives the same numbers as before since linear interpolation of R and X is exact for a series RL.

### D3. Sensitivity and yield

- Per-part sensitivity of the worst-case VSWR over the band (analytic derivatives through the ABCD cascade, checked against finite differences), shown on each ladder card and as a ranking: which part dominates the error.
- Tolerance analysis with correlated parts (parts from one reel drift together; a correlation setting per kind), worst-case corners, and design centring: move the nominal values to maximize yield within tolerances.
- Auto match ranks solutions by sensitivity and yield as well as by Q, and says why.
- Done means: derivatives agree with finite differences to 1e-6, design centring raises yield on reference cases, and the ranking is explained in the UI.

Status, 2026-10-25: implemented; QA round done (last item below).

- Sensitivity: `packages/core/src/sensitivity.ts`. dE/dp in closed form for every element kind and parameter (R, L, C value and Q, with a package's Cp, ESR, ESL and pads; the r, l and c of RLC blocks in both connections and orientations; the transformer ratio; line and stub length and Z0, the lossy line's attenuation included), the product rule along the cascade (prefix and suffix products, one pass per frequency), dZin, dGamma towards Z0 or a complex target, d|Gamma| and dVSWR. At a perfect match |Gamma| is a cone: dGamma is exact, d|Gamma| and dVSWR are reported as 0. Over a band: the derivative at the frequency of the worst VSWR, and the smooth alternative, the power mean of order 32 of the VSWR over the band (between max N^(-1/32) and max; weights (VSWR_k / S)^(p-1) / N). Per-percent sensitivities. Checked against central differences (relative step 1e-5) for 19 element variants inside a four-part ladder at three frequencies (`packages/core/test/sensitivity.test.ts`): worst relative error per kind 2e-11 (R) to 4e-9 (packaged C), all under the 1e-6 asked; the band derivatives of the worst case and the power mean to 1e-6 as well.
- Ranking: `spreadShares` linearizes the change of Gamma under the tolerances and gives each part its Euler share of the variance (sigma_i Re(a_i conj(sum_j rho_ij sigma_j a_j)) / Var, a_i = dGamma/dp_i p_i); the shares add up to 1, are plain variance shares without correlation and negative for a part whose correlated drift offsets another. On Gamma rather than |Gamma|, so it holds at a perfect match (the QA round below ranks by the VSWR instead and keeps this as the fallback at a match). Predicts the Monte Carlo RMS of Gamma within 3 % at 1 % tolerances. App: `packages/app/src/lib/sensitivity.ts`, the network the Tolerance panel analyses (realized with Realize on, the measured load model over the band), the design frequency and the band, weighted by the power-mean weights; the Tolerance panel's table (part, tolerance, VSWR per %, share bar) and sentence, and a share bar on each ladder card while the panel is open.
- Tolerance analysis: correlation per part kind (L, C, R) through one shared normal factor per kind and run, exact for normal draws and through a Gaussian copula with r = 2 sin(pi rho / 6) for uniform ones; every coefficient 0 keeps the old draws in the old order (no existing test changed). Correlation reproduced within 4 standard errors at 20 000 draws (rho 0.8 and 0.3, both distributions). Wilson 95 % interval on every yield (0/10: 0 to 0.2775, 5/10: 0.2366 to 0.7634, 81/263: 0.2553 to 0.3662, as published). Worst-case corners (`packages/core/src/yield.ts`): candidates from the sensitivities (the corner pushing Gamma furthest along its own direction and 16 others at each judged frequency, and the gradient signs of the worst VSWR and of the power mean), every candidate evaluated in the full network, and every corner as well up to 10 varied quantities; on five reference networks (both L matches at f0, an L match over 20 %, three parts with an RLC trap and a line) the corner is at least the worst of 3000 uniform samples and the sensitivities find it (within 1 %). The Monte Carlo worker returns the corner with each run.
- Design centring (`centreDesign`, worker `centre.worker.ts`): 300 common random numbers, mean shifting towards the passing draws, Nelder-Mead in log coordinates on a logistic-smoothed yield (wide, then narrow), bounds of the optimizer and half to twice each value; with Realize on the best combination of the series or stock neighbours (or the value as given) on the same draws; before and after re-measured on 2000 fresh draws with Wilson intervals; Apply is one undo step named after the gain. Reference cases (`packages/core/test/yield.test.ts`, 5 % parts, 900 MHz to 1.1 GHz): 100 - j50 ohm, shunt L + series C at VSWR 1.38: ideal values 74.2 % (72.2 to 76.0) to 99.0 % (98.4 to 99.3); E24 values (11 nH, 2.7 pF) 46.1 % (43.9 to 48.3) to 92.8 % (91.6 to 93.9) with 12 nH, 2.7 pF (99.0 % before snapping). 12 - j18 ohm, series C + shunt L at VSWR 1.31: ideal 75.3 % to 89.1 %; E24 44.3 % (42.1 to 46.4) to 56.5 % (54.4 to 58.7), where the series is too coarse for the centre (89.6 % before snapping). Under 0.1 s each.
- Auto match: each Add parts solution carries its yield (200 seeded runs of the whole network, judged as the Tolerance panel judges, 5 % parts with Realize off or the series tolerance with Realize on, a typed tolerance first) and its dominant part; Rank by Q, Yield (ties to the smaller spread of Gamma, then Q) or VSWR, explained in one line under the notes. On the reference load (100 - j50 ohm, 20 % band, VSWR 1.38) the shunt C + series L network ranks first by yield (100 %) over shunt L + series C (73 %), whose estimate agrees with a 4000-run Monte Carlo.
- QA round (2026-10-25). Ranking: the shares are now those of the variance of the quantity the yield is judged by (`scalarSpread`): the VSWR at the design frequency, the smooth band VSWR (power mean of order 32) over a band, from their first-order derivatives; the phase of Gamma, which does not change |Gamma| away from a match, no longer counts (broadband tour network at 100 MHz: Series C 1 was ranked first with 72 % at a VSWR slope of 8.5e-5; now Shunt C 2 67 %, Series C 3 23 %, Shunt L 4 9 %, Series C 1 0 %, the order of the yield each part costs alone). At or near a perfect match (nominal |Gamma| below the RMS change of Gamma) the ranking falls back to the mean square change of Gamma, the second-order term there, and says so; |Gamma| below 1e-9 counts as a perfect match in `sensitivityAt` (a synthesized match sits at 1e-16, where d|Gamma| was a projection on rounding noise and spoilt the band derivative by 1.3 %, which the oracle's new share check caught). A part typed as 0 has no tolerance slot, and a totally reflected band point is left out of the power mean. Worst case: the largest of the nominal network, every corner and the run's Monte Carlo samples (`worstRun`), labelled by source; a corner is not a bound where the response is not monotonic (quarter-wave line with 5 % length tolerance: nominal VSWR 4.000 against the best corner 3.985; low-Q parts at 24 %: run 1185 at 25.24 against the corner's 18.53; a trap tuned at f: nominal). Consistency: the Tolerance panel judges towards the design target (as Auto match did), and Auto match's yield is built with `toleranceSetup` of the design after Add (loss model, realized values, target, measured load, the panel's default tolerance), so both agree run for run on the same seed (lossy 15 - j40 ohm case: 58 of 200 in both, was 178 against 58). Centring: Apply only when the after interval lies above the before interval (or the gain exceeds the combined half-widths); `indices` lists the parts that moved, Apply writes only the parts whose shown value changes; the result names the judged range and the nominal worst VSWR before and after, flags parts at the edge of their range, and goes stale with any change, "no better centre" included; progress at every evaluation. Mutations of the centring and corner guards that survived (mean-shift and Nelder-Mead acceptance, own direction, gradient corners) are killed by `packages/core/test/yield-guards.test.ts`. The gradient corners are redundant in effect: the worst VSWR's gradient signs are the own-direction corner at the worst frequency, and the power mean's never beat the others in 4000 random networks.
- Oracle: `tools/oracle/d3_check.py`, run by `check.py`: the analytic dGamma/dp of three ladders (lumped with Q and packages, RLC blocks, lossy line, stubs and transformer; 23 parameters at three frequencies) against central differences of the scikit-rf ladder (1e-6); the Monte Carlo yield of an L match at f0 and over a band against brute-force integration over the tolerance box with numpy (801 x 801), the worst corner against all corners and the worst case against the grid, the spread shares over the band against numpy's central differences of the power mean (1e-6; 1.75e-8 after the QA round), the Wilson interval against the closed form, and the correlation of 10 000 correlated draws per distribution. The numpy checks were run locally (Python 3.12, numpy 2.5.4; the derivatives against a numpy ABCD port of `check.py`'s element models, 3.6e-11 to 7.9e-9; yields 0.1420 against 0.1416 and 0.9718 against 0.9713); the scikit-rf part runs in CI only (scikit-rf is not installed here).

### D4. The board in the network

- Stackup: εr and loss tangent over frequency (Djordjevic-Sarkar wideband model), copper thickness and roughness (Hammerstad or Groiss), entered once in Settings with presets for common FR-4 and Rogers laminates.
- Microstrip with dispersion (Kirschning-Jansen) and conductor and dielectric loss: `line.ts` uses the static Hammerstad-Jensen model today (no dispersion, no loss), which is fine for dimensions at low frequency and drifts at microwave frequencies.
- Board parasitics: pad capacitance per package and stackup, via inductance for every shunt part to ground (a via model from diameter and board thickness), and the interconnect traces between parts as microstrip segments with lengths.
- The as-built locus includes the board; the BOM and the report list the layout assumptions.
- Done means: models match published values (Kirschning-Jansen tables, via inductance formulas) and the oracle job covers the board elements.

Status, 2026-10-25: implemented and through a QA round (below).

- Stackup: `packages/core/src/stackup.ts`. Height, er and tanD at a reference frequency, copper thickness, RMS roughness and resistivity (IACS, 1.7241e-8 ohm m). The Djordjevic-Sarkar wideband Debye model in the form scikit-rf uses (f_low 1 kHz, f_high 1 THz, eps(fRef) = er (1 - j tanD)). Presets with their sources in the code: FR-4 1.6 mm and 0.8 mm (Isola 370HR data sheet rev. C: Dk 4.17, Df 0.0161 at 1 GHz), RO4003C 0.508 mm and RO4350B 0.762 mm (Rogers RO4000 data sheet: design Dk 3.55 and 3.66, Df 0.0027 and 0.0037 at 10 GHz); 1 oz copper with 3.2 um RMS (Rogers publication 92-243, table 1; for FR-4's HTE foil an assumption, its data sheet gives none). In the app: Settings > Board, stored like the package table (`smithonline.board.v1`; a substrate typed in the Dimensions dialog before D4 seeds it once).
- Microstrip: `packages/core/src/line.ts`. The static model is now Hammerstad-Jensen 1980 with their thickness correction (QuickSmith's 1975 formulas are gone: no 0.6 % step at W/h = 1; 50 ohm widths moved 0.50 to 0.67 %, all within 1.11 % of the published figures (RO4350B 1.11 %); FR-4, RO4350B and RT/duroid 5880 moved towards them, alumina away from its published 0.61 mm to 0.617 mm, towards the 0.620 mm of Wheeler's synthesis), the dispersion of eeff Kirschning-Jansen 1982 and of Z0 Jansen-Kirschning 1983 (R1, R2, R6 capped at 20 as qucsator does), conductor loss Rs / (Z0 W) Ki Kr with the Hammerstad-Jensen roughness factor (Groiss not used, documented), dielectric loss from the Djordjevic-Sarkar er and tanD; the complex permittivity runs through every formula, so Z0 and eeff are complex (scikit-rf's default, ADS-like mode). eta0 and mu0 are CODATA 2022. A `microstrip` element (width, physical length, a copy of the stackup) with the frequency-dependent ABCD; sensitivities to its length (closed form) and width (central differences of Z0 and gamma, about 1e-12); Monte Carlo varies its length like a line's; the optimizer bounds it to 10 to 170 degrees at band centre; dragging tunes its length. The Dimensions dialog uses the same model at the line's frequency (width for the dispersed Z0, length from the dispersed eeff, static values and loss shown) and offers **Use microstrip**.
- Board parasitics: `packages/core/src/board.ts`, `withBoard` (behind the app's `packagedElements` and `builtNetwork`). Pads from the land size (new **Land l**, **Land w** columns of the package table) and the stackup as the parallel plate plus the fringing at the four edges, C'(W) L + C'(L) W - eps0 er W L / h with C' from the static microstrip, replacing the table value (kept as the fallback for a package without a land size); a via (Goldfarb-Pucel, drill and dielectric height, N in parallel) in series with every shunt lumped part; a microstrip trace of one global length (0 = not modelled) between every two neighbouring lumped parts, of a set width or the width for the design Z0 at the design frequency. The parasitics are folded into the elements (`board` field), so the as-built ladder keeps one element per part and the arcs, markers and datapoint tables stay aligned. The as-built locus, the Response view's as-built curves, the `.s2p` export and the S-Plot entry include them; the BOM lists the layout assumptions under the table and the report adds them to the as-built datapoint table.
- Accuracy against the sources (`packages/core/test/board.test.ts`): Pozar's Example 3.7 (50 ohm on 0.127 cm, er 2.2): W/d 3.0828 against 3.081 (0.06 %), the quarter wave 2.19 cm as printed, eeff 1.881 against Pozar's 1.87 from Hammerstad's simpler formulas (0.6 %, the difference between the two models). Against scikit-rf 2.2.0's MLine with the same model choices: static eeff and Z0 on alumina, eeff and Z0 with dispersion from 1 to 40 GHz, and complex Z0, complex eeff, alpha_c, alpha_d and beta on RO4003C and FR-4, each to 1e-9 in the test (observed 1e-11 and better). `line.ts` is a line-by-line port of scikit-rf's `skrf/media/mline.py` (credited in its header and in `THIRD_PARTY_NOTICES.md`), so this agreement shows that the port is faithful, not that the model is right. The checks independent of scikit-rf's code are the review of each formula against its published form and Keysight ADS's MLIN on scikit-rf's regression data (`qa-d4-ads.test.ts`, the data in `packages/core/test/fixtures/ads/`): within 0.014 dB and 0.26 degrees in S21 and 0.56 dB and 2.0 degrees in S11 over 0.2 to 20 GHz (100 points), against scikit-rf's own tolerance of 0.1 dB and 1 degree (S21) and 1 dB and 10 degrees (S11). - Part model: `packages/core/src/parts.ts`. A two-port Touchstone file (S, Z, Y or H, at most 20 001 frequencies) becomes a library part: manufacturer, part number, type (C or L from the sign of the reactance at the lowest frequency), the measured S-parameters and a fitted equivalent circuit. Fixtures: series-through (S11 + S21 = 1 for an ideal fixture, the part impedance is the chain matrix's B, which is 2 Z0 (1 - S21) / S21 for ideal data) and shunt-through (S21 - S11 = 1, Z = 1 / C, which is Z0 S21 / (2 (1 - S21))); `detectFixture` picks the identity the data keeps and says when it cannot, the user can override, and data that cannot be read the chosen way (series-through data has no C element) is refused. S12 and S21 are averaged, so the part is reciprocal like every element. Interpolation: linear in the real and imaginary parts of S, chosen because S is bounded where Z (parallel resonance of an inductor) and Y (series resonance of a capacitor) are not, a convex combination of passive matrices stays passive, and it is scikit-rf's default; on the synthetic files (201 points from 10 MHz to 10 GHz) it is within 2e-4 in S of the generating circuit between the samples and within 0.5 % in Z below half the resonance. Outside the data the part has no value: `partAbcd` returns NaN, `partRangeProblem` says why, and nothing is extrapolated. From the data: nominal value (the effective value at the lowest frequency), effective value, ESR and Q at a frequency, self-resonance (sign change of the reactance, bisection on the interpolated data), all within 1e-4 (nominal), 5e-4 (resonance) of the generating circuits. The fitted circuit: a capacitor as C, ESL and ESR in series (w X = ESL w^2 - 1/C, a relative least-squares line), an inductor as L with series R across Cp (Cp from the resonance and L from the series branch left when Cp is taken away, iterated); exact to 1e-6 on the synthetic capacitors and within 1e-4 (L), 1e-3 (R) on the inductors.
- Element: a `part` kind (`PartElement`: orientation, the library part, board parasitics). A series part from a series-through file is the measured two-port; every other placement is the derived impedance as a series impedance or a shunt branch, with the via of the board in series with a shunt branch; the card flags a placement across the fixture (shunt from series-through: no ground path or grounded pad in the data; series from shunt-through: the fixture's ground path stays in Z). It evaluates everywhere the ladder does (chart, arcs, Response, S-Plot network, `.s2p`, stress, the board's vias and traces). Not varied or tuned: sensitivity (no parameters), Monte Carlo and centring, the optimizer, dragging. SPICE and LTspice write the fitted circuit and say so in a comment; the CKT netlist writes it as an RLC statement with a comment; `.xmlsc` refuses with a message. The `.s2p` export refuses a range past a part's data and says which part.

### D6. Closed loop: measure, compare, retune

- Import the measured S11 of the built board, overlay it on the designed response, and fit which parts and parasitics moved (least squares over part values and the board parameters of D4, with the sensitivities of D3 to keep it well conditioned).
- Suggest retune values snapped to the series or the library, and show the expected result.
- Done means: on synthetic data with known drifts the fit recovers them, and the suggestion brings the simulated result back inside the target.

Status, 2026-10-27: implemented, QA round 1 fixed (one blocker, nine majors, the minors; see the changelog).

- Model: `packages/core/src/closedloop.ts`. The network as built (`withBoard`: the realized values, the package parasitics, pads from the land size, vias, traces) with drift parameters on top: each part value scaled by 1 + x, capacitance added to each inductor's and capacitor's pads (both lands; half at each end of a series part, half at the node of a shunt part; offered only where the network as built has pads), all pads scaled, the vias scaled, the traces lengthened, εr and h scaled (pads, vias, traces and every microstrip of the network follow; offered only where something depends on them), and the reference plane (a matched delay between the VNA's calibration plane and the board, Γ times exp(-j 4π f τ); it belongs to the measurement, so the retune and the target figures leave it out, and it is never judged against a board built as designed, only against the range the fit takes, ±1 ns, about 20 cm of cable). A library part has a value parameter of its own, a scale on its measured impedance (on the series element of its two-port, or on the impedance derived from it; approximate, the data is of one sample), and on the board a pad parameter with nominal 0 (the data is of the part; the board's lands add capacitance). Prior widths (the scale of each parameter and the width of the regularization): 10 % for values, 5 % for a library part's scale (a typical tolerance of an RF part; the library holds none), 0.2 pF for a part's pads, 50 % for all pads and the vias, 1 mm for traces, 10 % for εr and h, 20 ps for the plane. Free by default: part values, the pads of parts that have pads (and of library parts on the board), the vias and the traces; all pads, εr, h and the plane are offered but not free. The fit's load at port 2 is the fixed load, the measured load (interpolatedLoad, measured points outside its band left out), or for a two-port file the VNA's termination; the retune and the designed figures always use the design's load.
- Fit: Levenberg-Marquardt on the complex Γ at the design's Z0, every measured frequency weighted alike, in prior-scaled coordinates, with a Tikhonov term per parameter of 1e-12 times its own squared column norm at no drift (a weak but resolvable parameter is shrunk by about 1e-12 of its drift, like a strong one). The Jacobian of a part value is D3's analytic dΓ/dvalue (`sensitivityAt`, checked against central differences to 1e-6 in the test, rotated by the plane); the board parameters and a library part's scale take central differences. The reference plane starts from a scan of the plane alone over ±1 ns in steps of 1/(40 f_max) (the residual repeats every 1/(2 f), so no minimum falls between steps; only the rotation is computed per step), from the slope of the phase of the measured over the designed Γ (phase steps between neighbours, each wrapped, weighted by the smaller |Γ|², so a match where the phase is noise counts little) and from none; each start runs three iterations, the lowest cost runs on to the end (the 300 ps case converged to -137 ps from none alone). Identifiability, before the fit at the start point: columns are taken largest remaining first (as QR with column pivoting); one whose cosine with a column taken before it is above 0.99875 (less than 5 % of it outside the other: one moves the response as the other does) is fixed and named with it ("acts like"), and one that is a numerically exact combination of those taken (less than 1e-6 of it outside their span) is fixed and named as a combination. A column merely close to the span of several is fitted: whether the data resolves it depends on the noise, which the next rule judges (the earlier 5 %-of-the-span rule set the series C's pads aside as "acts like Shunt L 1 pads, correlation 0.91" when the plane was free, though the data resolves them to 0.015 pF). After the fit a parameter whose standard uncertainty is half its prior width or more is fixed and named, the rest fitted again from where they were. Fitted pairs whose estimates correlate above 0.95 are reported: when one of the two lies within two of its uncertainties of no drift, "X or Y: these two cannot be told apart by this data" (the data fixes their joint effect, not which moved); when both are resolved, that they move together (each ± includes it). Uncertainty: the square root of the diagonal of s² (JᵀJ + D)⁻¹, D the per-parameter weights, s² the residual sum of squares over 2N - P; with D that small the bias is far below sigma (checked on clean data to 1e-7 of the drift and within 3 sigma with noise; over 200 seeds per case the 1 and 3 sigma coverage holds). Refused: fewer than 3 usable frequencies, no parameter, more than 2N - 2 unknowns, a network without value at a measured frequency.
- Checks (`checkFit`), what a bench engineer looks at before acting on a fit, each a stated rule: (1) the floor: the larger of the noise floor from the point-to-point scatter (each point against the line through its neighbours, normalized, the median over ln 2; within 15 % of the true noise from 3e-4 to 3e-3 in the test) and the instrument's accuracy, the smooth error its calibration leaves that the scatter cannot see: a setting in Build, Measured board, VNA class lab (0.002, -54 dB, the default) or hobby such as a NanoVNA (0.02, -34 dB, from its directivity and source match after an SOL calibration; taken by default for a NanoVNA or LibreVNA file); the floor used is the one printed, with the scatter when it is below. (2) The residual RMS over that floor: up to 3 noise, up to 10 "explains most, not all", above 10 "the model does not explain this board". A 0.03 directivity error with a 1 ns ripple is 10.2 floors on a lab VNA (unexplained) and 1.02 on a hobby one (its retune then holds on the true board). (3) A fitted drift above 3 prior widths or past the physical (negative pad or trace, value to 5 %) is implausible; the plane only beyond ±1 ns. (4) The design frequency must lie in the measured span. (5) With the plane not ticked, the same parameters are fitted again with it, silently, and the drop in the residual sum of squares tested against the residual variance with the plane: F = ((RSS0 - RSS1)/k)/(RSS1/(2N - P1)), k the parameters the plane adds, its p-value from the F distribution (regularized incomplete beta, checked against closed forms and scipy). The plane is called when p is below 0.001 and the residual RMS falls by a tenth of the floor or more: the first says it is no chance (300 clean seeds of the sample: 1 below 0.001, 5 below 0.01, 18 below 0.05, as an F distribution gives), the second that it matters (a 2 ps plane significant against a 0.0012 scatter but changing the RMS by 3e-5 is nothing to act on). Then the verdict says "a reference-plane offset of about +30.8 ps (about 5.1 mm of FR-4 microstrip) explains this measurement better: tick Reference plane and fit again" and the fit is not trusted. Decision: the plane stays unticked by default (after a calibration at the board's connector there is none) and this comparison runs on every fit; the advice to tick it is never given when it is ticked or when the design frequency lies outside the data. (6) The board was built from the source the measurement records (the realization source at Compare, kept with the measurement): after a change the verdict says "this measurement was taken on a board built from E24 values; the design now uses the part library" instead of pointing at the plane. A fit that fails a rule is shown in warning style in Build, the Response panel and the status line, each reason once, and the retune is refused with the first reason.
- Retune: `suggestRetune` with candidates from the design's source (`retuneCandidates`: six values each side in the series or the stock, the 13 nearest library parts that cover the band and are below resonance), judged at the band frequencies inside the measured span (refused when none is). A board inside the target needs no change; an empty band is refused. Every single change; when none reaches the target, every pair over the seven values nearest each part when more than three parts can change, and when none of those does, every pair over all options of all changeable parts (about 2,500 combinations for six parts); when no pair does, coordinate descent over all parts from the best of the board as it is, the best single and the best pair, then pruned (a change whose removal keeps the result inside, or no worse, is dropped), and with more than two changes left the pairs among those parts over all their values. Each candidate is evaluated from impedances and matrices of the network as built kept per frequency, so a combination costs its changes, not the parts (equal to the full model to 1e-12 in the test), and with a bound: the band in order of the board's own VSWR, worst first, given up once past the best found (exact for every comparison it is used in); sixteen parts over 201 band points with E96 take about 0.3 s. The suggestion is the fewest changes that reach the VSWR limit over the band (Tolerance's band, else the sweep, else f), else the lowest worst VSWR found, and only when it is lower than the board's as it is: otherwise no suggestion and no Apply ("no change of the parts in reach does better than the board as it is"; from the part library a change to 4.7 pF gave 1.879 against 1.783 before). The part to change first is the single change when it is enough, else the change that helps most alone. A fitted value drift stays with its place; a library part put in is taken as measured (its scale drift was the old part's). A retune inside the target by less than 15 % of (limit - 1) says the margin is small, names the drift that stands out most, and that a new batch needs that cause fixed rather than the retune copied. Apply places exactly what was evaluated (a library part as a library part element where Realize would not map the value back to it); Realize compares neighbouring values on the whole network, so a change can make it pick another value for a part the retune did not change (E96: the series C from 2.74 to 2.67 pF, 1.36517 promised, 1.34540 built): such a part is set to what the board has, locked where Realize would still move it, and named in the status line; when the network as built still differs from what was evaluated, Apply refuses with the reason. A heuristic search, documented as such.

### D7. Broadband matching from data

- The real frequency technique (Carlin, and the simplified form of Yarman and Carlin) computes the best achievable transducer gain shape for the measured load over the band and realizes it as a ladder, compared side by side with the topology search and the Bode-Fano floor.
- Done means: on textbook loads the result matches published RFT examples, and on reference loads it meets or beats the topology search for the same part count.

## Validation outside the code

- A built board: design a match for a real load, build it with real 0402 parts, measure it on a VNA (a NanoVNA is enough for a first check), and compare measured with predicted S11 in the app (D6 makes this a feature). This needs the owner's hardware and is the only check of the whole chain.
- RF engineers who did not build the app, using it on their own loads.

## Order and size

D1 first, because everything else rests on it. Then D2 and D3, which deepen the existing band tools. D4 and D5 bring the board and the parts in. D6 closes the loop and needs D3 to D5. D7 is the largest algorithmic step and comes last. Each phase is a release.
