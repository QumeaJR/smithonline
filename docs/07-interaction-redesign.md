# Interaction redesign: phone, tablet and desktop

Status: agreed design, 2026-10-24. Produced by an interaction review of the running app at 375, 768 and 1440 px and a visual design proposal, reconciled in a second round. This document is the hand-over for the implementation phases in section 7; `docs/03-ui-design.md` is updated at the end of phase 7.

Goal: the app works on an iPhone with every feature and option, and every interaction (tapping, scrolling, menus, sheets, dialogs, sliders, dragging points, forms) is clean and intuitive at every size, in the restraint of Apple's Human Interface Guidelines. Density stays; confusion goes.

## 1. What is wrong today

Measured on the build of 2026-10-24.

- Phone: the header wraps to four rows (175 px) and is not sticky; the page is one 2200 to 3000 px scroll, so the chart is out of view while anything is edited; the chart swallows page scrolling (`touch-action: none`); 101 controls are under 44 px (tiny buttons 17 px, sliders 16 px, checkboxes 13 px, help links 15 px); datapoint markers are 15 px and can sit 10 px apart; there is no touch equivalent of right-click, double-click or wheel zoom; the File menu is clipped 40 px off the left edge; Settings is taller than the viewport with its footer below the fold and the package table overflowing; tool panels and the tour overlay the chart and can stack; "hover to preview" has no touch meaning; ladder reorder uses HTML5 drag, which iOS never fires.
- Tablet (768 px) gets the phone layout although it has room for the chart beside a panel.
- Desktop: opening Auto match halves the chart at 1440 px (padding) and overlays it below 1251 px, two models for one tool; the Examples menu overflows the right edge at 1440 px; Escape closes tool panels but not the tour; a drag or a palette placement writes no status message; the schematic strip values collide at narrow widths; no transitions anywhere; icons are Unicode glyphs and one emoji; `window.confirm` is used for the sweep scaling question.

## 2. Decisions

1. **Phone navigation: chart hero plus a persistent bottom sheet.** No tab bar, no mini chart. A tab bar makes chart and network mutually exclusive and costs a switch per adjustment; a sheet at the half detent keeps the upper part of the chart and two ladder cards on screen together, which is the live loop the product is built on.
2. **Tool panels live in the right column at every width.** The right column gets a strip "Numbers | Auto match" (or Optimize band, Tolerance) at its top; the chart never resizes and is never covered. On the tablet it is the side column's segment, on the phone the sheet's Tools segment. The `with-tool` padding and the overlay tool panel go.
3. **One overlay model.** Menus, the context menu, suggestions, Import and dialogs are popovers or dialogs on pointer devices and sheets on coarse pointers, positioned by a pure function that flips and clamps to the viewport. One Escape stack: top overlay, then an armed part, then the tour.
4. **Touch targets.** 44 px controls on coarse pointers, 28 px on fine; 36 px table rows and small buttons on touch; markers get an invisible 44 px halo with nearest-centre picking.
5. **Dark mode follows the system by default** (the existing auto state); the toggle cycles auto, dark, light.
6. **Nothing that is data animates.** Loci, points, tables and readouts update in the same frame as the input. Only chrome moves: popovers, sheets, dialogs, segmented thumbs, switches, the Fit reset of the chart view (200 ms).

## 3. Visual system (tokens)

Tokens are CSS custom properties at the top of `packages/app/src/index.css`. Old names stay as aliases until phase 7. The chart colours `--grid-z`, `--grid-y`, `--marker`, `--dp-user`, `--sweep`, `--vswr`, `--q`, `--stab`, `--gain`, `--noise` and the element palette are unchanged; Settings writes them inline and reads them back by name. `--mc-cloud` is split from `--danger` so the error colour can be a true red.

- Type: UI font `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`; mono `ui-monospace, "SF Mono", Consolas, Menlo, monospace`. Scale: caption 11/14 500 (uppercase section headings, 0.06 em), small 12/16, body 13/18, emph 13/18 600, title 15/20 600, display 20/24 600; mono table 11.5/16, mono field 12/16 (16/20 on coarse pointers, which stops iOS zooming on focus), mono readout 13/18 500, mono big 15/20 600. `font-variant-numeric: tabular-nums` on every readout and table; `-webkit-text-size-adjust: 100%` on html.
- Spacing: 4 px base, `--space-0..8` = 2, 4, 8, 12, 16, 20, 24, 32; gutter 16 px on the phone, 12 px in side panels.
- Control heights: `--control-h` 28 / `--control-h-sm` 22 / `--control-h-lg` 36 on fine pointers; 44 / 36 / 50 under `(pointer: coarse)`.
- Radii: xs 4 (chips, swatches), sm 6 (buttons, fields, menu items), md 8 (cards, popovers), lg 12 (dialogs), xl 16 (sheet top corners), full for badges and switches.
- Elevation: flat by default; shadow-1 for a segmented thumb, shadow-2 for popovers and menus, shadow-3 for dialogs and sheets; dark mode raises surfaces one tone instead of relying on shadow. Backdrop rgba(0,0,0,.25) light, .5 dark.
- Colours, light: canvas #f2f3f5, surface #ffffff, inset #f6f7f9, raised #ffffff, border-subtle #e6e9ed, border-strong #cfd5dc, text-primary #1b1f24, text-secondary #5a6472, text-tertiary #8a94a1, accent #0b6bcb, accent-hover #0959a8, accent-soft #e3f0fd, on-accent #ffffff, danger #c92a2a, danger-soft #fdeaea, warning #e8590c, success #2f9e44, focus ring accent 2 px offset 2 px. Dark: canvas #0e1217, surface #161b22, inset #11161c, raised #1c232c, border-subtle #232c38, border-strong #36414f, text-primary #e6edf3, text-secondary #9aa7b5, text-tertiary #6b7786, accent #58a6ff, accent-hover #79b8ff, accent-soft #15283d, on-accent #0b1220, danger #ff6b6b, danger-soft #3a1d1d, warning #ffa94d, success #51cf66.
- Motion: `--dur-fast` 120 ms (hover, pressed, toggles), `--dur-base` 160 ms (segmented thumb, switch, popover), `--dur-slow` 280 ms (sheet detents, dialogs); ease-out cubic-bezier(0.2, 0, 0, 1), ease-std cubic-bezier(0.2, 0, 0.2, 1). `prefers-reduced-motion`: all durations 0.
- Viewport: `100dvh` instead of `100vh`, `env(safe-area-inset-*)` on the top bar, the status bar, the sheet and the tour panel; `viewport-fit=cover` and `theme-color` metas.

## 4. Components

Each is a class in `index.css` and, where it has behaviour, a component under `src/components/ui/`.

- **Button**: primary (one per surface), secondary (default), quiet (menu rows, help links), icon (square, inline SVG from `ui/icons.tsx`, aria-label required; replaces every Unicode glyph and the lock emoji), sm (replaces `.btn.tiny`, alias kept), toggle (`aria-pressed`), destructive (quiet, danger text). On coarse pointers the small buttons of a ladder card row collapse into one overflow button with Move up, Move down, Dimensions, Winding, Delete.
- **Field**: label, input and a unit suffix in one box; width derived from a `digits` prop; `ValueInput` keeps its engineering notation, Enter commits, Escape reverts, invalid flash. Coarse pointers: 16 px font, 44 px height, `enterKeyHint="done"`, `inputMode="text"` (the iOS decimal keypad has no minus sign and no letters, which engineering notation needs), autocomplete, autocorrect and autocapitalize off.
- **Segmented control**: replaces the view tabs, the Ideal/Realized toggle, the Dimensions medium switch and the Response linear/log switch. Role tablist, arrow keys move, thumb slides 160 ms. The five Auto match methods do not fit at 375 px: on the phone they become a chooser row ("Method: Add parts") that opens a sheet with the five methods and their one-line descriptions, grouped as the guide groups them; the segmented control stays on tablet and desktop.
- **Switch**: for modes (Realize, Losses, sweep enabled, judge over band, keep frequency, datapoint input); checkboxes stay for lists. 28 x 16 px on fine, 44 x 26 px on coarse pointers, always a 44 px hit area; `<input type=checkbox role=switch>`.
- **Slider**: 4 px track, 16 px knob on fine and 28 px on coarse pointers, 44 px hit area, `touch-action: pan-y` on the track so a vertical swipe scrolls the sheet; one undo step per drag; keyboard repeats within 500 ms coalesce into one step; Realize mode shows series ticks and snaps.
- **Ladder card**: header row (grip on pointer devices, badge, name, summary value, overflow button on touch), fields row, tune row (slider, value, Reset), secondary lines (node impedance, stress, realized line, note). Selected: accent border. Reorder by pointer events on the grip (long press on touch), arrows as the fallback. Dragging a card out of the list and releasing it anywhere outside it (on the chart, on another panel, outside the window) removes the element: while the pointer is outside the list the dragged card shows a remove cue (danger border and a remove icon) and the list closes the gap, releasing inside the list again cancels, and the status message names the removed part with an inline Undo.
- **Tables**: mono, tabular nums, sticky header; rows 24 px on fine, 36 px on coarse pointers; first column sticky and horizontal scroll in narrow containers; the datapoints table shows #, Z, VSWR, RL by default on the phone with a column chooser for |Γ|, ∠Γ and Q (stored beside the chart options).
- **Menu and popover**: anchored, positioned by `positionOverlay(anchorRect, size, viewport)` which prefers the anchor's alignment, flips when it would leave the viewport and clamps to the gutter; keyboard Up, Down, Home, End, Enter, Escape, typeahead; focus returns to the opener. On coarse pointers the same component renders as a sheet with 44 px rows and the descriptions kept.
- **Sheet** (`ui/Sheet.tsx`): grabber, optional header, scrollable body with `overscroll-behavior: contain`, safe-area bottom padding, top corners xl. Detents: peek (64 px plus safe area), half (defined in pixels as just below the chart hero, not in dvh, because Safari's toolbar changes dvh by about 60 px), full. Drag the grabber or header to move; a fast downward flick closes dismissible sheets (menus, context, suggestions, dialogs); the main panel sheet never goes below peek. 280 ms ease-out.
- **Dialog**: scrolling body and a sticky footer at every width (`max-height: calc(100dvh - 40px)` on desktop); on the phone a full-screen sheet with a top bar (Cancel or Done). One shared focus trap and focus return for Settings, Report, Help, Dimensions, Winding and Import; Escape goes to the top dialog only; dialogs never scroll the page. The package table in Settings scrolls horizontally with a sticky first column. Dialogs whose content is compared with the chart (Dimensions, Winding, Report, Import) are draggable by their title bar on fine pointers and remember their position for the session, so they can be moved off the part of the chart being read; Settings and Help are not.
- **Status**: desktop and tablet keep the 28 px status bar with the live readout and the message; messages can carry an inline Undo (8 s) or an action. On the phone: a toast of at most two lines for 4 s (8 s with Undo); the last message stays in the readout chip on the chart, truncated to one line, and a tap on the chip expands it; errors and refusals stay as a banner until dismissed. The store keeps the convention that Undo and Redo repeat the step's message, and drags and placements get labels ("Moved TP2 to 32 + j5 Ω", "Placed Shunt L 16 nH").
- **Banners for modes**: an armed part ("Shunt L armed: tap, or press and drag, to place it" with Default and Cancel) and datapoint input mode ("Tap the chart to add DP3" with Done) are states, not events; they show as the sheet's peek header on the phone and as a bar under the chart toolbar on desktop, since the phone has no Escape.
- **Progress**: the three workers render a determinate bar with "done of total, best" in the tool strip or sheet header; a badge dot on the tool button while a job runs behind another segment; stale results show a note with Run again; never a spinner over the chart.
- **Start guide**: the "Start a match" hint no longer sits over the chart. It is a card at the head of the ladder, directly above the load card where the chain begins, with three steps that tick off as they are done: 1 set the load (done once the load differs from the default or a datapoint was added), 2 set the target (done once a target is set, with a note that Z0 is the default), 3 match (done once the ladder has a part), each step with a button that focuses the matching control (the load fields, the target card, Auto match). A close button hides it and the choice is remembered in the browser; Help has a "Show the start guide" entry that brings it back, and a new design shows it again only when the guide was never closed. On the phone it is the first Network card. Experienced users see it once.
- **Empty states**: title, one line, up to three steps, one action; for the empty ladder, Response without a sweep, S-Plot without files, Monte Carlo without parts.
- **Tooltips**: pointer devices keep the `title` tips; on touch there is no hover, so every heading has a 28 px help link that opens the guide at its section, and the Tools rows carry the one-line descriptions the header tooltips carry today.

## 5. Layout per width

Breakpoints: phone below 700 px, tablet 700 to 1099, desktop 1100 to 1439, wide 1440 and up.

- **Desktop and wide**: three columns as today (248/288 asides on desktop, 300/360 on wide). Header 48 px in groups that follow what the controls do, each group a bordered cluster with a hairline between neighbours and a wider gap between groups: left (brand, view segmented control), centre (design strip: name, f, Z0, power in one bordered group, then Undo and Redo), right in three clusters: data (File, Examples, Share link, since all three move designs in and out), design tools (Auto match, Optimize band), settings (Tolerance, Settings), then Help and Theme as icon buttons. On the phone the More sheet lists the same clusters as titled groups. The right column carries the tool strip; the tour stays at the top of the left column and joins the Escape stack.
- **Tablet**: two columns, chart left at 60 percent (at least 440 px), one side column (at least 320 px) with a segmented control Network | Numbers at its top; an open tool is a third segment with its own close; the schematic strip stays under the chart; the status bar stays; menus are popovers that flip inside the viewport.
- **Phone**: top bar 44 px plus safe area: More (icon button) opening a sheet with the groups Data (File, Examples, Share link), Settings (Tolerance opens its tool, Settings, Theme) and Help; the view segmented control with short labels (Chart, Response, S-Plot) or icons with the active label; Undo and Redo icon buttons. The chart is full width and square, pinned, with three chips: the design chip top left ("450 MHz · 50 Ω", plus the power when set; tap opens a sheet with name, f, Z0, power), the grid button top right (Z, Y, density, Labels, Fit in a small sheet), the readout chip bottom left. The main sheet below with the segmented control Network | Numbers | Tools: Network holds the schematic strip (64 px, scrollable, values with 3 significant digits in cells sized to their content), the palette as a disclosure "Add part" with two rows of six 52 px tiles (open when the ladder is empty, collapsed to one row otherwise), the Realize and Losses switches and the ladder; Numbers holds the right panel sections; Tools lists Auto match, Optimize band, Tolerance with descriptions, each pushing its panel into the sheet with a back chevron that does not stop a running job. At full detent a 36 px live strip at the top of the sheet shows Zin and VSWR; tapping it drops the sheet to half. Arming a part or pressing a marker drops the sheet to peek and restores the previous detent after place, cancel or release. The tour is the sheet header at peek (title, step, Next) and the full narration at half, paged with Next; starting a tool during a tour ends the tour with an Undo toast. Response and S-Plot stack their plots in a scrolling page under the top bar with the sheet at peek; cursor readouts come from touch drag on the plot with the readout row pinned under it; the S-Plot sheet holds the file list, the gain table and the export form.

## 6. Chart gestures

| Gesture | Pointer | Touch |
|---|---|---|
| Pan | drag on empty area | one-finger drag on empty area |
| Zoom | wheel about the cursor | pinch about the midpoint; two-finger drag pans; limits as today |
| Fit | button | Fit in the grid sheet and a tap on the readout chip |
| Readout | pointer move | finger down and moving shows the readout in the chart's top band (two lines: z and Z, then Y and Γ), which replaces the design chip and grid button for the duration; at rest the last values sit in the readout chip |
| Drag a point | drag the marker | 44 px halo, nearest-centre pick on pointerdown (the selected point wins a tie); the readout names the picked point the instant the finger lands; the finger offset is kept; release without movement records no step; two markers within 12 px get a chooser row in the context sheet |
| Place an armed part | click, ghost follows the hover | press, drag to aim (ghost follows), release to place; a plain tap places at once; two-finger pan still works while armed; the banner carries Default and Cancel |
| Suggestions | double-click | double tap on a marker only; on empty chart "Suggest a match to here" is the first row of the context sheet |
| Context menu | right-click | long press 400 ms with 10 px slop, on a marker or on empty chart; the marker pulses 1.2x; the sheet is titled with the point ("TP3, 32.1 + j4.5 Ω") with a destructive Remove row and the element grid |
| Select | click | tap |

Markers 12 px and labels 1.15x on coarse pointers (not 1.4x, which worsens overlaps). Implementation notes for `chart/SmithChart.tsx`: pointer events with capture in a `Map<pointerId, point>`, handle `pointercancel`; the pinch needs native non-passive listeners and must cancel Safari's `gesturestart` and `gesturechange`, as the wheel handler already does; the SVG needs `-webkit-touch-callout: none` and `user-select: none` so a long press shows no selection callout; `touch-action: none` on the SVG only once the chart no longer sits in a scrolling page (interim: `pan-y` on coarse pointers in phase 1). The gesture arithmetic lives in a pure `chart/gestures.ts` and is unit tested in node.

Component tests use `// @vitest-environment jsdom` with `@testing-library/react` (dev dependencies added in phase 2); layout and gesture maths stay in pure modules tested in node. Old class names stay as aliases until phase 7.
